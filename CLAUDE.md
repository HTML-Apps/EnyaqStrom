# EnyaqStrom – Hinweise für die Arbeit am Code

- Aufbau: `index.html` (HTML + kleine Früh-Skripte + Firebase-Modul), **App-Logik in `src/*.js`**, `sw.js` (Service Worker), `api/` + `lib/` (Vercel-Funktionen).
- **`app.js` ist generiert**: `src/*.js` werden in Namensreihenfolge unverändert zu einem Skript zusammengehängt (`npm run js`).
  Nie `app.js` direkt bearbeiten. Ein einziges Skript wie früher inline → Funktionen gelten dateiübergreifend, Reihenfolge = Dateiname.
- **Tailwind ist vorab gebaut** (`npm run css`, scannt `index.html` und `src/**/*.js`) → `app.css`.
- Nach Änderungen: `npm install` (einmalig), dann **`npm run make`** (js + css), `app.js`/`app.css` mit einchecken.
  Das Skript heißt bewusst nicht `build`: Vercel würde es sonst selbst ausführen und danach einen Ordner `public` erwarten → Deploy schlägt fehl.
  Danach in `index.html` (`/app.js?v=…`, `/app.css?v=…`) und `sw.js` (`SAME_ORIGIN_ASSETS`, `CACHE_VERSION`) die Version erhöhen.
- Klassen nur als vollständige Wörter schreiben (nicht per String zusammensetzen), sonst findet Tailwind sie nicht.
- `CACHE_VERSION` in `sw.js` bei jeder Auslieferung erhöhen.
- Bilder je Auto in Unterordnern: `Bilder/Enyaq/` (alles Enyaq-spezifische inkl. `hero/`), `Bilder/Epiq/` (Epiq1–2 + `hero/`, im Karussell beim Fahrzeugtyp Epiq über `CAR_HERO`; aufbereiten mit `python3 tools/epiq_bilder.py`, siehe LIESMICH.md).
  Gemeinsame Bilder (Icons, Wetter `wx/`, Statistik, Fahrzeugakte, Shortcuts) bleiben direkt in `Bilder/`.
- Karussell-Bilder auf Start: vorab aufbereitet in `Bilder/Enyaq/hero/` (weißer Rand entfernt, zugeschnitten, WebP 1100 px).
  Werte `aspect`/`extra` stehen in `HERO_IMGS` (src/05-startseite-banner.js). Bild 1 steht zusätzlich direkt im HTML und wird vorgeladen.
- Maßbilder (Enyaq7–9, Originale in `Bilder/Enyaq/`): mit `python3 tools/hero_masse.py` freistellen und Bemaßung hell umfärben → `Bilder/Enyaq/hero/7–9.webp`.
- Einfache Ansicht (Papa-Modus): Einstellung `ui: 'simple'` (Fahrzeug & Kauf → Ansicht), Logik in `src/17-einfach.js`, Ausblenden per CSS `html.simple …` in index.html; Drawer-Einträge mit `data-easy` bleiben sichtbar.
- Testkonto ohne Auto: in `SKODA_ACCOUNTS` `{"mail@gmail.com": {"demo": true}}` → `/api/vehicle` liefert feste Beispielwerte.
- Škoda-API: Freigabe je Konto in `SKODA_ACCOUNTS` – entweder `{key, vin}` oder nur `{"allow": true}`; dann trägt der Nutzer VIN + Schlüssel selbst in der App ein (Einstellungen › Konto & Sync › „Fahrzeug verbinden“, Karte auf Start, Onboarding-Schritt). Beides verschlüsselt in `enyaqStrom/<uid>/settings/skoda` (`lib/fs.js`, `lib/auth.js`), hat Vorrang vor `SKODA_ACCOUNTS`.
- Fahrtenbuch per Teilen-Menü (Android, installierte App): `share_target` in `manifest.json` → POST `/share-target` wird im `sw.js` abgefangen, Datei im Cache `enyaq-share` abgelegt, Weiterleitung auf `/?go=fb-share` → Import in `src/18-teilen.js`.
- Test-Screenshots nie im Repo-Ordner ablegen (Scratchpad nutzen).
- Voreinstellungen je Konto einmal beim ersten Anmelden (Markierung `presetV` in den synchronisierten Einstellungen, ergänzt nur Fehlendes): `USER_PRESETS` in `src/11-cloud-drive-sicherung.js`, Schlüssel = SHA-256 der E-Mail (Repo ist öffentlich, keine Adressen im Klartext).
- Onboarding beim allerersten Öffnen (Willkommen + Google-Anmeldung, 3 Fragen, Tour in der einfachen Ansicht): `src/19-onboarding.js`, Fortschritt in `enyaq.onb`. Einladungslink `/?auto=epiq` setzt das Auto schon vor der Anmeldung. Wer Daten hat, sieht es nicht.
- Dauerhafte Google-Freigabe (Tasks + Drive ohne Google-Fenster): `api/google.js` (OAuth mit Refresh-Token, verschlüsselt in `enyaqStrom/<uid>/settings/google`), Vercel-Variablen `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`, Weiterleitungs-URI `https://enyaqstromapp.vercel.app/api/google`. App: `driveToken` in index.html nimmt bei Merker `enyaq.gLinked` das Server-Token; Knopf unter Einstellungen › Sprachbefehle.
- Ladebild Enyaq: am Handy `Bilder/Enyaq/Enyaq_live.webp` (angeschnitten), bei breiter Bildfläche (Seitenverhältnis ≥ 1,8, Desktop) `Enyaq_live-voll.webp` (`CAR_LIVE_WIDE` in src/05-startseite-banner.js, links bündig: Kabelende = linker Rand von `main`); freistellen mit `python3 tools/enyaq_live.py` (Original `Enyaq_live-voll-original.png`, vorhandener Schatten bleibt).
- Keine `alert()`/`confirm()`: eigene Dialoge in `src/20-dialoge.js` – `appNote(text)` (Hinweis unten), `await ask(text, {title, ok, cancel, danger})` (Rückfrage, Handler dafür `async`), Löschen ohne Rückfrage mit `undoDel(text, undo)` bzw. `labUndo(text, labSnap())`.
- PC ab 1280 px, Einstellungen: `showView` setzt `html.set-desk` → `#set-drawer` steht fest links statt des Schnellmenüs (kein Abdunkeln, kein Burger), unten `#sd-home` „Start“; CSS im 1280-px-Block von index.html.
- Einstellungs-Sync schreibt nur geänderte Schlüssel: `pushPrefs` vergleicht mit dem letzten Cloud-Stand `enyaq.setBase` und nutzt `cloud.patchPrefs` (setDoc mit `mergeFields`, Löschen per `deleteField`). Nie wieder das ganze `settings`-Objekt pushen, sonst überschreibt ein Gerät mit altem Stand neuere Werte.
- Heller Modus: Seitenhintergrund `bg-slate-100` (dunkel `bg-black`); Seitenüberschriften `text-slate-900 dark:text-white`; der Start-Kopf (`#hero-bg`) bleibt dunkel und läuft unten per Maske aus.
- Hell/Dunkel per Klasse (`darkMode: 'class'`): Früh-Skript im `<head>` setzt `html.dark` aus `enyaq.theme` (auto/light/dark, nur dieses Gerät), Umschalter `#theme-seg` unter Fahrzeug & Kauf. Eigenes CSS mit `html.dark …` / `html:not(.dark) …` statt `@media (prefers-color-scheme)`, in JS `isDark()`; Wechsel löst `themechange` aus.
- Start-Hintergrundfarbe (`KEY_HERO`) und Darstellung (`enyaq.theme`) gelten nur je Gerät, nicht in `SYNC_SET_KEYS` aufnehmen.
- Wochencheck Akku-Pflege (`src/21-wochencheck.js`): einmal pro Woche ab Montag beim Öffnen von Start, Score Ende letzter Woche vs. Vorwoche (`batCare(now)` zählt nur Ladungen bis `now`), Gesehen-Markierung `nCare` (synchronisiert). Vorschau: `careWeekShow(true)`.
- Google-Tasks-Übernahme (`gtImport`): erst speichern, dann abhaken; holt auch in 14 Tagen erledigte Aufgaben ohne Wert nach (außer selbst gelöschte: `labStamp` merkt `del['src:…']`). Messwerte (`lab`) werden beim Hochladen per Transaktion mit dem Cloud-Stand zusammengeführt (`cloud.mergePrefs`), `labMerge` entfernt doppelte `src`.
- Software-Updates (Wissen › Updates): `pend` = angekündigt (ohne `inst`, zählt nicht für Vergleich/Markierungen), `ann` = angekündigt am, `chg` [{t, seen}] = „Was ist neu“ (`chgParse` macht aus eingefügtem Text Punkte), `text` = „Mein Eindruck“. `upInstall` setzt Datum + km vom Auto; Start-Hinweis `#up-banner` (`renderUpBanner`).
- Abend-Push (`api/ice-push.js`, ein Zeitplan 17:00 UTC): Eis-Warnung an Geräte mit `devices[id].ice` (fehlt = an), fällige Erinnerungen an Geräte mit `rem: true` – nur am Fälligkeitstag bzw. wenn der km-Stand seit dem Vorabend (`settings/pushState.remKm`) die Fälligkeit überschreitet. Getrennte Nachrichten (`tag`), Erinnerung mit `kind: 'rem'` → eigene Bilder im `sw.js`. App: `pushKind('enyaq.icePush'|'enyaq.remPush', an)`, Test `POST {test:'rem'}`.
- Akku-niedrig-Push (im selben Abendlauf `api/ice-push.js`): Gerät mit `devices[id].low` = Schwelle in % (App: `enyaq.lowPush`, Einstellungen › Fahrzeug und Laden, nur mit verbundenem Fahrzeug). Beim Einschalten `POST {low:'reg'}` → E-Mail verschlüsselt an die uid gebunden in `settings/lowPush`, damit der Zeitplan die Škoda-Zugangsdaten findet. Nicht bei angestecktem Auto; bei Frost Schwelle + 10. Test `POST {test:'low'}`, Bilder `kind: 'low'` im `sw.js`.
- Fehlerprotokoll: Früh-Skript im `<head>` sammelt `error`/`unhandledrejection` in `enyaq.errs` (max. 40, gleiche zusammengefasst); `src/22-fehlerprotokoll.js` zeigt sie unter Konto & Cloud (Kopieren/Leeren) und meldet sie angemeldet an `api/errlog.js` (Sammlung `enyaqErrLog/`, nur Server). Entwickler-Konto (SHA-256 der E-Mail in `ADMINS`) sieht „Alle Geräte“.
